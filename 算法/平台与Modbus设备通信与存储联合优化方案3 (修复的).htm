1.5 核心优化目标

满足协议、存储限额与业务要求的多目标联合优化，优先级从高到低：

1.       合规性目标：100%符合Modbus协议约束与设备硬件限制，无越界、非法报文；

2.       目标1：最小化设备总存储占用（查询命令存储+上发报文缓存预留）；

3.       目标2：最小化全生命周期总通信开销（1次配置下发 + w次高频数据上发）；

4.       效率目标：算法执行效率最优，适配大规模变量、多从站场景，无计算膨胀问题；

5.       灵活性目标：支持设备存储限额约束与w交互式调整，灵活平衡存储与通信开销。

3 问题转化与算法选型

3.1 问题核心约束与转化

1.       强制分组约束：按「从站地址+区号」分组，每组独立优化，不可跨组合并；

2.       区间合法性约束：同组变量排序后，仅可合并连续区间，且合并后总寄存器个数不超过分区单次最大读取量；

3.       全覆盖约束：所有合法变量地址无重叠、无遗漏，仅被一个查询命令覆盖；

4.      存储硬约束：最终方案总存储占用 用户配置的设备存储限额；

5.       问题转化：每组寻找最优区间分割点，在硬约束下实现双目标总开销最小，属双目标一维区间最优划分问题。

3.2 算法选型依据

1.       基础核心算法：动态规划+帕累托优化，生成全局非劣解集，避免贪心算法局部最优缺陷，完美适配双目标优化场景；

2.       效率优化算法：滑动窗口最值优化，将动态规划时间复杂度从O(n²)降至O(n)，适配大规模变量场景；

3.       必做配套体系：全流程无损失剪枝，彻底解决帕累托优化过程中解数量指数级膨胀问题，在不丢失全局最优解的前提下，将算法复杂度控制在工业场景可接受范围；

4.       鲁棒性配套：全链路异常处理与告警机制，覆盖所有非法场景与边界场景，保证生产环境稳定运行。

 

4 算法详细设计

4.1 预处理流程（无损失源头剪枝）

预处理是算法合规性的基础，同时通过无损失源头剪枝从根源减少变量规模，完全不影响优化精度，为所有场景必做环节。

4.1.1 合规性校验

对所有输入变量进行合法性校验，拦截非法变量，避免后续算法执行异常：

1.       地址范围校验：变量起始/结束地址必须在0-9999范围内，且结束地址≥起始地址；

2.       长度超限校验：单个变量寄存器个数不得超过对应分区单次最大读取量；

3.       地址重叠校验：同「从站地址+区号」分组内，变量之间不可存在地址重叠。

4.1.2 无损失源头剪枝

所有剪枝操作均无精度损失、不丢失全局最优解，从源头降低算法计算量：

1.       重复变量过滤：对同一「从站地址+区号+起始地址+结束地址」的重复定义变量，仅保留1个，剔除冗余重复变量；

2.       空分组过滤：变量数为0的分组，直接剔除，不进入后续优化流程，避免无效笛卡尔积计算；

3.       连续无间隙变量预合并：对同分组内地址完全连续、无任何空隙的变量，提前合并为单个变量单元。

> 无损失依据：完全连续无间隙的变量，合并后无任何无效地址增加，不改变最优解的开销计算，同时直接减少动态规划的输入规模n，降低计算量。

4.1.3 分组与排序

1.       分组：按「从站地址+区号」对合法变量进行强制分组，每组独立执行优化；

2.       排序：同组内变量按起始地址升序排序，保证区间合并的合法性；

3.       预计算：为每个变量预计算起始地址、结束地址、占用寄存器长度，用于后续区间开销计算。

4.2 核心定义与状态设计

2.      0区/1区：整数优化后，解耦为窗口内的最小值+常数项。

•       窗口约束：合法j范围为（为满足单次最大读取量的最小j）；

•       单调性证明：随i递增而递增，因此随i单调不减，完全符合滑动窗口的应用特征；

•       实现方案：用单调递增队列维护窗口内的最小值，将单步状态转移的时间复杂度从O(n)降至O(1)，整体动态规划时间复杂度从O(n²)降至O(n)。

4.5 帕累托非劣解筛选

本环节为动态规划过程中的实时剪枝，针对的候选解进行无损失筛选，避免解数量随变量数n指数级增长，所有操作均不丢失全局最优解，为必做环节。

4.5.1 同k值去重剪枝（无损失）

•          核心逻辑：当两个候选解的查询项数k完全相同时，仅保留最小的解；

•          无损失依据：k相同的情况下，更小的解，存储占用更小、通信开销也更小，完全支配同k的其他所有解，其余解不可能成为全局最优解，剔除后无任何精度损失；

•          效果：可直接将单dp状态的解数量降低一个数量级，是控制解膨胀的核心操作。

4.5.2 硬件约束前置剪枝（无损失）

•       核心逻辑：在生成候选解时，直接剔除超过设备全局最大存储限额的解；

•          无损失依据：设备的最大可用存储是固定硬约束，超过该限额的解业务上完全不可用，不可能成为最终推荐方案，提前剔除不会丢失有效最优解，同时避免无效状态转移；

•          扩展适配：支持按分区设置独立存储占比阈值，进一步收紧约束，适配不同设备的分区内存差异。

4.5.3 基础帕累托非劣解筛选规则

完成上述必做剪枝后，执行标准帕累托筛选，保留非劣解：

1.       计算每个候选解的；

2.      按升序、升序排序；

3.       遍历剪枝，仅保留小于当前最小值的解，最终得到该状态的帕累托非劣解集合。

4.6 分组合并增量剪枝（无损失）

本环节解决多分组场景下解数量指数级膨胀问题，为多从站、多分区场景的必做环节，完全不丢失全局最优解。

4.6.1 核心逻辑与无损失依据

•          核心逻辑：采用「边合并、边剪枝」的增量模式，而非「全部分组合并完成后一次性剪枝」；每合并一个分组，就立刻执行帕累托筛选，用剪枝后的精简解集合去合并下一个分组；

•          无损失依据：帕累托非劣解的合并与筛选具有结合律，「先合并分组1+2并剪枝，再合并分组3并剪枝」与「一次性合并全部分组再剪枝」，最终得到的全局最优解完全一致，不会丢失任何有效解。

4.6.2 具体操作步骤

1.       初始化全局解集合：将第一个分组的帕累托前沿作为初始全局解集合；

2.       增量合并：取下一个分组的帕累托前沿，与当前全局解集合做笛卡尔积，生成临时候选解；

3.       实时剪枝：对临时候选解执行帕累托非劣解筛选，仅保留有效非劣解；

4.       更新全局解：用剪枝后的精简解集合替换原全局解集合；

5.       重复步骤2-4，直到所有分组合并完成，最终得到全局帕累托前沿。

4.6.3 效果说明

若存在10个分组，每个分组2个非劣解：

•       传统一次性合并：中间解数量峰值为个，易出现内存溢出；

•          增量剪枝合并：每一步解数量均控制在常数级（如≤50个），内存占用降低95%以上，计算效率提升1-2个数量级。

 

5 完整算法执行流程

1.       输入接收：接收业务变量信息、设备硬件约束参数（分区最大读取量、存储限额）、业务参数（预估上发次数w）；

2.       预处理与源头剪枝：执行合规性校验，触发异常则输出告警并拦截非法变量；完成无损失源头剪枝、分组与排序；

3.       单组独立优化：对每个分组执行滑动窗口优化的动态规划，每步执行无损失实时剪枝，生成单组帕累托非劣解；

4.       分组合并与增量剪枝：执行增量合并与实时剪枝，生成全局帕累托前沿；

5.       全局合法性校验：对全局解进行硬约束校验，存储限额不足时触发告警，输出兜底最优方案；

6.       交互式优化：根据用户输入的存储限额、w值，筛选可行解，计算并推荐核心通信开销最小的最优方案；

7.       报文生成与合规校验：根据最优方案生成符合协议规范的寄存器读取配置与下发报文，完成报文合规性校验，触发异常则输出告警；

8.       结果输出：输出最优方案明细、开销计算结果、标准下发报文与告警日志。

 

6 时间复杂度分析

1.       预处理阶段：核心耗时为同组变量排序，时间复杂度为（为第i个分组的变量数，总变量数V）；

2.       动态规划阶段：经滑动窗口优化后，单组时间复杂度为O(V_i)，全部分组总时间复杂度为O(V)；

3.       分组合并阶段：经增量剪枝后，每一步解数量控制在常数级，总时间复杂度为O(M)（M为分组数）；

4.       整体时间复杂度：由组内排序主导，为，经全流程无损失剪枝后，实际运行效率提升1-2个数量级，完美适配工业级大规模变量、多从站场景。

 

7 交互式优化升级（存储限额+w调整）

基于全局帕累托前沿，分两阶段实现交互式优化，适配工程灵活决策，同时补充参数合法性校验与告警。

7.1 离线预计算阶段（仅执行1次）

1.       生成全局帕累托前沿；

2.      预计算每个非劣解的、、，结构化存储；

3.      按升序排序，便于在线快速筛选。

7.2 在线交互式优化阶段（可反复调整）

1.      参数接收与合法性校验：接收用户输入的存储限额、预估上发次数w（支持多个值对比），参数非法时触发告警；

2.      可行解筛选：保留的非劣解，无可行解则触发告警，推荐存储占用最小的兜底方案；

3.      最优方案计算：对每个w值，筛选最小的可行解，输出方案明细与开销计算结果；

4.       多维度对比：生成多w值方案对比表格与趋势图，直观展示不同上发频率下的最优方案差异，辅助用户决策。

9.2 常见问题解答

1.       为何不用贪心算法？

贪心算法仅能实现局部最优，无法兼顾存储与通信双目标优化，易出现极端场景下的开销劣化；动态规划+帕累托优化可生成全局非劣解集，保证所有场景下的最优解覆盖。

2.       必做的无损失剪枝会丢失全局最优解吗？

不会。所有必做剪枝环节均仅剔除「被完全支配」「业务不可用」「冗余无效」的解，保留所有可能成为全局最优的非劣解，数学上可证明不会丢失最优解。

3.       0/1区向上取整会影响优化精度吗？

不影响。算法严格遵循协议字节对齐规则，所有开销计算均严格按照向上取整规则执行，无任何近似处理，保证优化精度与实际开销完全一致。

4.       w值如何预估？

按业务上发频率与配置有效期计算，例如：配置有效期1年，每日上发1次，w=365；10秒上发1次，配置有效期1天，w=8640。

5.       增量剪枝为何是无损失的？

帕累托非劣解的合并具有结合律，增量合并剪枝与全量合并剪枝的最终结果完全一致；增量剪枝仅在每一步剔除无效解，不会影响最终全局最优解的生成。
