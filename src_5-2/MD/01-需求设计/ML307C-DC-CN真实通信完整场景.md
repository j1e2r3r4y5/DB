## 场景概述

### 项目背景
本场景描述了一个真实的工业数据采集系统，使用 **ML307C-DC-CN 单芯片 DTU** 方案。从设备启动开始，完整演示所有7个功能码（0x00~0x06）的使用，包括配置存储视角。

### 系统角色说明

| 角色 | 功能 | 实现方式 |
|-----|-----|---------|
| **ML307C-DC-CN** | 单芯片 DTU，运行你的代码 | OpenCPU |
| **Modbus 从站设备** | 温度/湿度/电力/继电器 | 真实传感器 |
| **云端 IoT 平台** | 数据存储、设备管理、配置下发 | MQTT Broker |

### 真实项目配置

| 变量名 | 站号 | 分区 | 地址 | 数量 | 数据类型 |
|-------|-----|------|------|-------|------|
| 开关状态 | 1 | 线圈 | 0x0000 | 1个线圈 | bit |
| 温度数值 | 1 | 保持寄存器 | 0x0000 | 2个寄存器 | float32 |
| 湿度数值 | 1 | 保持寄存器 | 0x0002 | 1个寄存器 | uint16 |
| 功率数值 | 1 | 保持寄存器 | 0x0003 | 4个寄存器 | float64 |
| 电能数值 | 1 | 保持寄存器 | 0x0007 | 2个寄存器 | int32 |
| 设备描述 | 1 | 保持寄存器 | 0x000A | 10个寄存器 | string(20字节) |

## 核心芯片规格对比

| 对比项 | ML307C-DC-CN（扩展版） | ML307C-DL-CN（标准版） | STM32F103C8T6 |
|--------|------------------------|-------------------------|------------------------|
| 芯片平台 | 翱捷科技 ASR1605 SoC | 翱捷科技 ASR1605 SoC | ARM Cortex-M3 |
| 主频 | **614MHz** | 614MHz | 72MHz |
| 运行内存(RAM) | **4MB pSRAM** | 4MB pSRAM | 20KB |
| 程序存储(Flash) | **4MB** | **2MB** | 64KB |
| OpenCPU 支持 | ✅ | ❌ | 无 |
| 操作系统 | 内置 FreeRTOS | 无（仅 AT 固件） | 无（需自行移植） |
| 开发方式 | C 语言 SDK + Lua 5.3 | 仅 AT 指令 | 纯 C 语言 |
| **结论** | **推荐用于新项目开发** | **仅用于透传模式** | 主流通用 MCU |

## 完整通信场景流程（包含所有功能码 + 存储视角）

### 场景时序总览（T = 分钟）

```
┌─────────────────────────────────────────────────────────────────────────┐
│  严格按功能码顺序交互：0x01→0x02→0x03→0x04→0x05→0x06 │
└─────────────────────────────────────────────────────────────────────────┘

T=00:00 设备上电启动
├─ Flash 读取默认配置
├─ 连接 4G 网络
└─ MQTT 连接 Broker，订阅下行主题

T=00:10 心跳包（0x00）→ 平台接收
└─ 仅设备→平台：[0000]

T=00:15 平台→设备（0x01）模组配置查询
└─ 设备→平台（0x01）响应：[0100001E05]

T=00:20 平台→设备（0x02）模组配置下发（上报间隔改为60秒）
├─ 设备保存到 Flash
├─ 重启定时器（现在是60秒上报）
└─ 设备→平台（0x02）响应：[0200]

T=00:25 平台→设备（0x03）数据配置查询
└─ 设备→平台（0x03）响应：[03000006...]（当前采集点列表）

T=00:30 平台→设备（0x04）数据配置下发（完整6个数据点）
├─ 设备保存到 Flash
└─ 设备→平台（0x04）响应：[0400]

T=02:00 数据上报（0x05）→ 根据0x02和0x04配置
└─ 上报6个数据点（开关、温度、湿度、功率、电能、设备描述），按60秒间隔

T=03:00 平台→设备（0x06）远程置数（线圈0置ON）
├─ 设备执行 Modbus 写线圈或直接 GPIO 控制
└─ 设备→平台（0x06）响应：[06000000000100]
```

### 第一步：设备上电启动（T=00:00，存储视角）

```
┌─────────────────────────────────────────────────────────────────────────┐
│                  1. 设备上电启动（存储视角）                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  【存储操作 1 - 读取 Flash 默认配置】                                  │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │ FLASH 存储区域（ML307C-DC-CN）                             │   │
│  │ ┌─────────────────────────────────────────────────────────┐   │   │
│  │ │ 设备序列号： "ML307C001"                               │   │   │
│  │ │ MQTT Broker： "192.168.1.100:1883"                     │   │   │
│  │ │ 上报间隔：30秒（0x001E）                               │   │   │
│  │ │ Modbus 波特率：9600                                   │   │   │
│  │ │ 数据采集点列表：                                       │   │   │
│  │ │  - 数据点1：从站1，线圈0x0000，长度1，开关状态         │   │   │
│  │ │  - 数据点2：从站1，保持寄存器0x0000，长度2，温度       │   │   │
│  │ │  - 数据点3：从站1，保持寄存器0x0002，长度1，湿度       │   │   │
│  │ │  - 数据点4：从站1，保持寄存器0x0003，长度4，功率       │   │   │
│  │ │  - 数据点5：从站1，保持寄存器0x0007，长度2，电能       │   │   │
│  │ │  - 数据点6：从站1，保持寄存器0x000A，长度10，设备描述  │   │   │
│  │ └─────────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                          │
│  【启动流程】                                                           │
│  ML307C 上电启动 → FreeRTOS 运行 → 应用程序 main() 开始执行             │
│                                                                          │
│  1. 调用 SDK：fs_read("/config/device_config.bin") → 读取到 RAM          │
│  2. 解析配置：获取设备序列号、Broker 地址、采集点列表（6个）              │
│  3. 初始化 UART2（Modbus），波特率 9600                                 │
│  4. 初始化 GPIO（继电器控制引脚，输出模式）                               │
│  5. 初始化网络栈 → 连接 4G 网络 → 注册到电信                             │
│  6. 调用 SDK：mqtt_init("192.168.1.100", 1883, "ML307C001")               │
│  7. 调用 SDK：mqtt_connect() → 等待连接成功回调                          │
│  8. 调用 SDK：mqtt_subscribe("/dtu/ML307C001/down", 2)                    │
│  9. 创建 FreeRTOS 定时器：                                               │
│     - 心跳定时器：os_timer_create(30000, heartbeat_handler)             │
│     - 数据上报定时器：os_timer_create(120000, data_report_handler)      │
│ 10. 应用就绪，进入循环（FreeRTOS 任务调度）                              │
│                                                                          │
│  【存储影响】无写入操作，仅从 Flash 读取到 RAM                          │
└─────────────────────────────────────────────────────────────────────────┘
```

## RAM占用变化分析（逐帧慢动作）

### 先讲清楚：RAM 像什么？

为了方便理解，我们把 RAM 想象成一个**写字台**：

| RAM 区域 | 对应写字台 | 说明 |
|---------|-----|-----|
| **静态区** | **固定抽屉** | 永远在那里，存放长期要用到的东西（配置表、通讯录、采集点列表） |
| **栈** | **临时草稿纸堆** | 函数调用时拿一张写，调用完就扔掉，最多的时候叠好几层 |
| **堆** | **可移动文件夹** | 按需申请，大东西用大文件夹，不用了就收起来 |
| **DMA 区** | **固定收件箱** | 网络、串口自动收东西的地方，大小固定 |

---

### RAM分区详解（简单翻译）

| 分区类型 | 大白话 | 大小 |
|---------|-----|-----|
| **静态变量区** | 固定抽屉 | 2 KB |
| **栈** | 临时草稿纸 | 1-4 KB（按调用深度变化） |
| **堆** | 可移动文件夹 | 0-8 KB |
| **DMA 缓冲区** | 固定收件箱 | 1 KB |

---

### 逐帧慢动作时间线（边读边组装，更节省内存！）

#### 【慢动作前的背景】
此时系统的**稳定状态**（还没开始上报）：
| 区域 | 占用（字节） | 说明 |
|-----|----------|-----|
| 静态区 | 2048 | 设备配置、MQTT句柄、6个采集点列表 |
| DMA | 1024 | 固定的网络收发缓冲区 |
| 堆 | 904 | 6个采集点列表(392) + MQTT收发缓冲区(512) |
| 栈 | 0 | 没有函数调用 |
| **总** | **3976** | 约 3.88 KB |

---

#### 【慢动作开始】T=00:00

##### 第0.0秒：定时器触发，开始上报 + 预分配缓冲区

```
触发：report_timer_cb()

步骤：
├─ 第1层：report_timer_cb() → 栈 + 64 字节
├─ 在堆上分配上报消息缓冲区（256字节） → 现在堆：904+256 = 1160 字节
├─ 先填充Header：05 00 06（功能码0x05，6个点）
└─ 现在总 RAM：2048+1024+1160+64 = 4300 字节 (4.20 KB)
```

---

##### 第0.1秒：读数据点1（开关状态），边读边追加

```
子步骤：
1. 进入 modbus_read_coils() → 栈 + 72 字节
2. 分配临时Modbus缓冲区 → malloc(128) → 堆现在：1160+128 = 1288
3. 组装请求、接收响应、解析 OFF
4. **关键！** 追加8字节标识 + 1字节值到上报缓冲区
5. 释放临时Modbus缓冲区 → 堆回到1160
6. 返回

此时总RAM峰值：2048+1024+1288+152 = 4512字节 (4.41 KB)
回到：2048+1024+1160+64 = 4300字节 (4.20 KB)
```

---

##### 第0.2-0.6秒：依次读数据点2-6，边读边追加

```
数据点2（温度）：
├─ 读保持寄存器2个 → 解析 float32
├─ 追加8字节标识 + 4字节值到缓冲区
├─ 峰值RAM类似 4.4 KB
└─ 追加完成，释放Modbus临时缓冲区

数据点3（湿度）：追加10字节
数据点4（功率）：追加16字节
数据点5（电能）：追加12字节
数据点6（设备描述）：追加28字节

每次峰值：堆1160+128=1288，栈约150，总约4512字节 (4.41 KB)
每次追加后恢复到约4300字节
```

---

##### 第0.7秒：所有数据点追加完毕，开始MQTT发布

```
上报缓冲区完整了（90字节）
调用 mqtt_publish() → 栈 + 320字节

此时【系统总RAM峰值】：
├─ 静态区：2048
├─ DMA：1024
├─ 栈：64+320 = 384字节
├─ 堆：1160（上报缓冲区还在）
└─ 总：2048+1024+1160+384 = 4616 字节 (4.51 KB)

【优化点】！ 峰值比原来的4.88KB低了！
```

---

##### 第0.8-0.9秒：MQTT发送完成，释放缓冲区

```
发送完成，从mqtt_publish返回 → 栈释放320，回到64
释放堆上报消息缓冲区 → 堆从1160回到904
从report_timer_cb返回 → 栈释放64，回到0

回到稳定状态：
├─ 静态区：2048
├─ DMA：1024
├─ 堆：904
├─ 栈：0
└─ 总：3976字节 (3.88 KB)
```

### 给资深开发者的优化建议

1. **堆复用（性能+内存优化）**
   - 0x05数据上报的Modbus临时缓冲区可以静态分配在堆，不用每次malloc/free
   - 上报消息缓冲区也可以预分配，永远保留256字节，虽然平时占一点，但效率大幅提升

2. **栈深度控制**
   - mqtt_publish()内部可以优化，把320字节拆小一些
   - 避免5层以上的函数调用链

3. **0x04配置下发新旧内存处理**
   - 方案A：提前预留更大空间（比如一开始就预留10个采集点）
   - 方案B：先写Flash，重启后重新加载（粗暴但安全）
   - 方案C：内存池技术

### 功能码协议交互汇总表

| 功能码 | 名称 | 方向 | 最小长度 | 存储影响 | 说明 |
|--------|------|------|---------|---------|------|
| 0x00 | 心跳包 | 上行 | 2 | 无 | 30秒或自定义间隔上报 |

| 0x02 | 模组配置下发 | 双向 | 下行4/上行2 | ✅Flash写入 | 修改上报间隔等配置 |

| 0x04 | 数据配置下发 | 双向 | 下行3+N*8/上行2 | ✅Flash写入 | 新增/修改/删除采集点，本场景为完整6个点配置 |

| 0x06 | 远程置数 | 双向 | 下行7/上行7 | 无 | 控制线圈、寄存器或GPIO |

## 常见问题 FAQ

### 关于本场景

1. **Q: 为什么配置操作（0x02,0x04）必须写入Flash？**
   A: 确保掉电重启后配置不丢失。如果只修改RAM，重启后会恢复默认值。

2. **Q: 实时操作（0x00,0x05,0x06）可以不写Flash吗？**
   A: 完全可以！这些都是临时操作，不需要持久化，仅RAM处理即可，效率也更高。

3. **Q: 如果在0x04保存过程中断电怎么办？**
   A: 建议采用双缓冲策略：
      - 先写入 /config/temp_config.bin
      - 验证完整性
      - 再重命名为实际配置文件
      - 启动时优先读取备份，避免损坏

4. **Q: OpenCPU模式下，RAM/Flash空间够用吗？**
   A: 完全够用！ML307C-DC-CN有4MB RAM + 4MB Flash，你的应用程序通常在100-500KB之间，剩下大量空间用于配置和数据缓冲。

5. **Q: 6个数据点上报会不会占用太多RAM？**
   A: 从逐帧分析看，峰值约4.88KB，对于4MB RAM来说非常小，完全不用担心。
