## 一、项目概述

本项目是一套完整的 4G DTU 物联网数据传输系统，包含以下组件：

- **前端**：Vue.js 3 物联网设备管理平台
- **后端**：Go Frame 微服务
- **MQTT Broker**：消息中间件
- **MySQL**：关系型数据库（存储设备、变量等配置）
- **InfluxDB 2.x**：时序数据库（存储历史数据）
- **DTU 模拟器**：模拟 4G DTU 设备与 Modbus 从站通信

## 八、InfluxDB 配置

### 8.1 InfluxDB 2.7.1

**重要**：本项目**必须使用 InfluxDB 2.x 版本**，原因如下：

1. **API 差异**：1.x 使用 `:9999` 端口和传统 HTTP API；2.x 使用 `:8086` 端口和 Flux 查询语言
2. **认证方式**：1.x 使用用户名密码；2.x 使用 Token 认证
3. **后端代码**：本项目后端代码使用 InfluxDB 2.x 的 Go SDK 和 API，无法兼容 1.x

| 特性 | InfluxDB 1.x | InfluxDB 2.x (本项目) |
| --- | --- | --- |
| 默认端口 | 9999 (API) | 8086 (API) |
| 认证方式 | 用户名/密码 | Token |
| 组织结构 | 无 | Org/Bucket |
| SDK | v1.x client | v2.x client |
| 本项目状态 | ❌ 不兼容 | ✅ 已配置 |

## 十一、协议说明

### 11.1 数据类型定义

| 值       | 类型名称     | 说明                     | 字节数 |
| :------ | :------- | :--------------------- | :-- |
| bool    | 布尔       | 0或1，按位存储               | 1位  |
| uint16  | 无符号16位整数 | 0-65535                | 2字节 |
| int16   | 有符号16位整数 | -32768-32767           | 2字节 |
| uint32  | 无符号32位整数 | 0-4294967295           | 4字节 |
| int32   | 有符号32位整数 | -2147483648-2147483647 | 4字节 |
| float32 | 单精度浮点数   | IEEE 754               | 4字节 |
| float64 | 双精度浮点数   | IEEE 754               | 8字节 |
| string  | 字符串      | 按字节存储                  | 变长  |

**数值转换公式**：实际值 = 原始值 × Scale + Offset

**字节序说明**：

- ABCD：大端序（高位在前）
- DCBA：小端序（低位在前）
- BADC：混合序
- CDAB：混合序

### 11.2 Modbus 区域定义

| 区域编号 | 官方名称                      | 数据类型  | 读写权限    | 功能码       |
| :--- | :------------------------ | :---- | :------ | :-------- |
| 0 区  | 线圈 (Coils)                | 1位布尔值 | **可读写** | 0x01/0x05 |
| 1 区  | 离散输入 (Discrete Inputs)    | 1位布尔值 | 只读      | 0x02      |
| 3 区  | 输入寄存器 (Input Registers)   | 16位字  | 只读      | 0x04      |
| 4 区  | 保持寄存器 (Holding Registers) | 16位字  | **可读写** | 0x03/0x06 |

### 11.3 功能码定义

| 功能码  | 名称     | 方向 | 说明                 |
| ---- | ------ | -- | ------------------ |
| 0x00 | 心跳包    | 上行 | 无内容心跳包，30秒发送一次     |
| 0x01 | 模组配置查询 | 下行 | 查询DTU当前配置          |
| 0x01 | 模组配置上发 | 上行 | 上发DTU当前配置          |
| 0x02 | 下发模组配置 | 下行 | 下发DTU配置（发送模式、波特率等） |
| 0x02 | 模组配置结果 | 上行 | 配置执行结果             |
| 0x03 | 数据配置查询 | 下行 | 查询DTU已配置的数据点       |
| 0x03 | 数据配置上发 | 上行 | 上发已配置的数据点          |
| 0x04 | 下发数据配置 | 下行 | 下发要采集的数据点配置        |
| 0x04 | 配置结果   | 上行 | 配置执行结果             |
| 0x05 | 数据上发   | 上行 | DTU定期上传采集的数据       |
| 0x06 | 远程置数   | 下行 | 写入Modbus寄存器        |

### 11.4 04下发/05上发协议详解

#### 04下发格式

```
04 00 01 01 04 00 00 00 02
04       = 功能码（数据配置下发）
00 01    = 数据组数 = 1（合并后的组数）
01       = 从站地址 = 1
04       = 类型 = 4（保持寄存器区）
00 00    = 起始地址 = 0
00 02    = 物理数量 = 2（读取2个寄存器：温度+湿度）
```

| 字段 | 字节数 | 说明 |
| --- | --- | --- |
| 功能码 | 1 | 固定为 0x04 |
| 数据组数 | 2 | 合并后的数据组数量 |
| 从站地址 | 1 | Modbus 从站地址 |
| 类型 | 1 | 0/1/3/4 区编号 |
| 起始地址 | 2 | 起始寄存器地址 |
| 物理数量 | 2 | 要读取的寄存器/位数量 |

#### 05上发格式

```
05 00 01 01 04 00 00 00 04 00 FA 02 58
05       = 功能码（数据上发）
00 01    = 数据组数 = 1（来自04下发的1组配置，合并了温度和湿度）
01       = 从站地址 = 1
04       = 类型 = 4（保持寄存器）
00 00    = 起始地址 = 0
00 04    = 数据长度 = 4字节（2寄存器×2字节）
00 FA    = 寄存器0值 = 250 (温度)
02 58    = 寄存器1值 = 600 (湿度)
```

| 字段 | 字节数 | 说明 |
| --- | --- | --- |
| 功能码 | 1 | 固定为 0x05 |
| 数据组数 | 2 | 来自04下发的数据组数 |
| 从站地址 | 1 | Modbus 从站地址 |
| 类型 | 1 | 0/1/3/4 区编号 |
| 起始地址 | 2 | 起始寄存器地址 |
| 数据长度 | 2 | 实际数据字节数 |
| 数据 | n | 实际数据内容 |

**解析规则**：
- 后端根据 MySQL 变量配置 (modbusType, modbusAddr) 来拆分数据
- 温度变量 (addr=0) → 取前2字节
- 湿度变量 (addr=1) → 取后2字节

function Test-ServiceHealth {

        [string]$ServiceName,

        Name = $ServiceName
        Status = "Unknown"
        Details = ""

            $result.Details = "Port $Port is listening"

            $result.Status = "Stopped"

                $result.Details = "$($result.Details) | Endpoint failed: $_"
            }
        }
    } catch {
        $result.Status = "Error"
        $result.Details = $_.Exception.Message
    }

    return $result
}

## 十七、常见问题

### Q1: 前端显示"暂无数据"

可能原因：

1. 尚未下发数据配置
2. DTU模拟器未正常运行
3. 变量配置与DTU上发数据不匹配
4. InfluxDB 连接问题

解决方法：

1. 确保已创建设备并完成配置下发
2. 确保已创建变量并下发数据配置
3. 检查变量配置的 modbusType、modbusAddr 是否与DTU采集配置一致
4. 检查 InfluxDB 是否正常运行：`Invoke-RestMethod -Uri "http://127.0.0.1:8086/health"`

### Q2: 下发配置后模拟器没有收到

可能原因：

1. MQTT 连接问题
2. 后端没有正确发送配置

解决方法：

1. 检查模拟器终端是否显示 "Subscribed to /dtu/A1B2C3D4/down"
2. 检查后端日志是否有 "下发数据配置" 相关日志
3. 检查 MQTT 连接数：`netstat -ano | Select-String ":1883" | Select-String "ESTABLISHED"`

### Q3: InfluxDB 端口 8086 未监听

可能原因：

1. 运行的是 InfluxDB 1.x 而不是 2.x
2. InfluxDB 服务异常

解决方法：

1. 停止所有 influxd 进程
2. 确保启动的是 InfluxDB 2.x：`Start-Process "C:\Users\JERRY\influxdb2\influxdb2_windows_amd64\influxd.exe"`
3. 验证：`Invoke-RestMethod -Uri "http://127.0.0.1:8086/health"`

### Q4: 前端 API 请求失败 (ERR_CONNECTION_REFUSED)

可能原因：

1. 后端服务未启动
2. 后端端口 8000 被占用

解决方法：

1. 检查后端进程：`Get-Process | Where-Object { $_.Name -like "*dev*" }`
2. 检查端口：`netstat -ano | Select-String ":8000.*LISTENING"`
3. 重启后端服务

### Q5: 开关(线圈)数据始终为0

可能原因：

1. 变量配置的 modbusType 错误（使用了1而不是0）
2. modbusAddr 地址不匹配

解决方法：

1. 检查变量配置：数据分区应选择"0区 线圈"，modbusType 应为 **0**
2. 检查地址：开关状态在DTU配置中的地址应为0
