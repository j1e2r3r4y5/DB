
## 数据类型支持改造分析报告

### 重要说明：协议不需要调整
经过讨论，明确了实际数据流：
- 前端配置变量 → 保存到 MySQL 变量表（包含数据类型）
- 后端下发 Modbus 读取配置 → 设备/模拟器只作为透传
- 设备/模拟器读取从站数据 → 原样上发 → 后端从变量表查数据类型进行解析

**结论：协议不需要任何调整！** 数据类型信息存储在 MySQL 变量表中，后端根据变量表进行解析。

---

### 需要支持的数据类型

| 类型名称    | 说明               | 存储方式     | 寄存器占用 | 字节长度            |
| :------ | :--------------- | :------- | :---- | :-------------- |
| bool    | 布尔值              | 0或1，按位存储 | 1位    | 1位/8=1字节(按字节对齐) |
| int16   | 有符号16位整数         | 2字节，大端序  | 1寄存器  | 2字节             |
| int32   | 有符号32位整数         | 4字节，大端序  | 2寄存器  | 4字节             |
| float32 | 单精度浮点数(IEEE 754) | 4字节，大端序  | 2寄存器  | 4字节             |
| float64 | 双精度浮点数(IEEE 754) | 8字节，大端序  | 4寄存器  | 8字节             |
| string  | 字符串              | 按字节存储    | 变长    | 变长              |

## 五、InfluxDB 数据存储调整

### 场景说明
每秒接收大量简单传感器数据 + 展示最新数据到面板

### 推荐方案：同时存原始值和解析值

#### 设计思路
- 写入时解析并存两份：原始值 + 解析后的数值
- 查询时直接读取解析后的数值，性能最好
- 保留原始值，方便未来重新解析

#### InfluxDB 存储结构

```
measurement: DataItem

tags:
  - dev_serial: 设备序列号
  - slave_addr: 从站地址
  - modbus_type: Modbus 类型
  - data_addr: 数据地址
  - data_type: 数据类型

fields:
  - raw_value: 原始字节的十六进制字符串（字符串）
  - parsed_value: 解析后的值的字符串形式（字符串，方便调试）
  - value_bool: 布尔值（布尔类型，仅当 data_type=0 时有值）
  - value_int: 整数值（整数类型，仅当 data_type=1/2 时有值）
  - value_float: 浮点值（浮点类型，仅当 data_type=3/4 时有值）
  - value_string: 字符串值（字符串类型，仅当 data_type=5 时有值）
```

#### 写入逻辑
1. 接收上发数据，从缓存表查 data_type
2. 解析数据，得到解析后的值
3. 同时写入 raw_value 和对应的 value_xxx 字段

#### 查询逻辑
1. 查询时根据 data_type 直接读取对应的 value_xxx 字段
2. 如果需要，可以提供从 raw_value 重新解析的备用逻辑

## 六、协议（不需要调整！）

### 数据配置下发协议（功能码 0x04）

**保持现有结构不变**：
```
[功能码:1][配置项数量:2][从站地址:1][Modbus类型:1][起始地址:2][数量:2]...
```

**不需要修改**：协议不需要添加数据类型字段

**数据类型处理**：
- 数据类型信息存储在 MySQL 变量表中
- 后端根据变量表计算 Modbus 读取长度（寄存器数量）
- 设备/模拟器按配置读取，不关心数据含义

### 数据上发协议（功能码 0x05）

**保持现有结构不变**：
```
[功能码:1][数据项数量:2][从站地址:1][Modbus类型:1][起始地址:2][数据字节长度:2][数据:N]...
```

**不需要修改**：协议不需要添加数据类型字段

**数据类型处理**：
- 设备/模拟器原样上发数据，不解析
- 后端从缓存表查 data_type，根据数据类型解析数据
