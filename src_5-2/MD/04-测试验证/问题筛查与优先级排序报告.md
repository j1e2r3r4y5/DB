### P0-01: 06远程置数协议格式解析错误 ✅ 已修复

**问题位置**：
- `simulator_v3/protocol/remote_write_handler.py` 第31-44行

**问题描述**：
协议定义06下发格式为：`1字节功能码 1字节类型 2字节开始地址 2字节数量 数值`
但代码中使用`quantity`字段来决定值的字节位置，这不符合协议定义。

**修复方案**：
修正value字节位置：线圈类型从`payload[7]`改为`payload[6]`，长度检查从8字节改为7字节

**修复状态**：✅ 已修复（2026-05-03）

### P1-02: 静默异常捕获导致数据丢失 ✅ 已修复 (Q-001)

**问题位置**：
- `simulator_v3/protocol/remote_write_handler.py` 第68-73行

**问题描述**：
所有异常都被静默捕获并返回`None`，调用者无法区分具体错误类型，可能导致重要操作失败被忽略。

**修复方案**：
1. 新增自定义异常类：
   - `RemoteWriteError`：基类异常
   - `PayloadParseError`：payload解析错误
   - `ModbusWriteError`：Modbus写入错误
   - `UnsupportedDataTypeError`：不支持的数据类型错误

2. 新增错误码常量：
   - `ERROR_CODE_SUCCESS = 0`
   - `ERROR_CODE_PARSE_FAILED = 1`
   - `ERROR_CODE_WRITE_FAILED = 2`
   - `ERROR_CODE_UNSUPPORTED_TYPE = 3`

3. 添加详细日志记录，包含时间戳、异常类型、错误信息及上下文数据

4. 返回结构化错误响应而非`None`：
   - `payload`太短返回错误码1
   - `struct.error`返回错误码1
   - `ModbusWriteError`返回错误码2
   - 不支持的类型返回错误码3

**修复代码**：
```python
class RemoteWriteError(Exception):
    def __init__(self, message: str, error_code: int, details: dict = None):
        super().__init__(message)
        self.error_code = error_code
        self.details = details or {}

def _handle_remote_write(self, payload: bytes) -> Optional[bytes]:
    if len(payload) < 7:
        timestamp = time.strftime('%Y-%m-%d %H:%M:%S')
        logger.error(f"[{timestamp}] Invalid remote write payload: too short (length={len(payload)})")
        return self._build_error_response(self.ERROR_CODE_PARSE_FAILED, {"reason": "payload_too_short"})

    try:
        # ... 正常处理逻辑 ...
    except struct.error as e:
        timestamp = time.strftime('%Y-%m-%d %H:%M:%S')
        logger.error(f"[{timestamp}] Failed to parse remote write payload: {type(e).__name__}: {e}")
        return self._build_error_response(self.ERROR_CODE_PARSE_FAILED, {"error": str(e)})
```

**修复状态**：✅ 已修复（2026-05-03）

**单元测试**：新增17个测试用例覆盖正常流程和异常场景

### P1-03: Modbus连接池心跳检测问题 ✅ 已修复

**问题位置**：
- `simulator_v3/core/modbus_master.py` 第91-100行

**问题描述**：
使用发送空字节`conn.sock.send(b'\x00')`来检测连接是否存活，可能在某些Modbus设备上导致协议错误。

**修复方案**：
1. 在`_create_connection`中添加`SO_KEEPALIVE`选项
2. 在连接验证时使用`recv(7, MSG_PEEK)`替代空字节发送

**修复代码**：
```python
# _create_connection中添加：
sock.setsockopt(socket.SOL_SOCKET, socket.SO_KEEPALIVE, 1)

# _get_connection中改为：
conn.sock.settimeout(0.5)
header = conn.sock.recv(7, socket.MSG_PEEK)
```

**修复状态**：✅ 已修复（2026-05-03）

### P1-07: 缺少重连次数限制 ✅ 已修复

**问题位置**：
- `simulator_v3/core/mqtt_client.py` 第184-199行

**问题描述**：
`_schedule_reconnect`方法会无限重连，如果MQTT Broker持续不可用，会不断消耗资源。

**修复方案**：
添加最大重连次数限制：
```python
self._max_reconnect_attempts = 10
self._reconnect_attempts = 0

# 在_schedule_reconnect中检查：
if self._reconnect_attempts >= self._max_reconnect_attempts:
    logger.error(f"Max reconnection attempts ({self._max_reconnect_attempts}) reached. Giving up.")
    return
```
