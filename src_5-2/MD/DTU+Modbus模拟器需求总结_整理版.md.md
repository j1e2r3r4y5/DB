# DTU+Modbus 模拟器需求总结\_整理版

你要开发的是一个**纯软件的一体化模拟器**，用来完整替代真实的硬件设备，让你的物联网平台可以在没有真实硬件的情况下完整运行、完成测试 —— 平台会完全以为自己在和真实的物理设备通信。

***

## 一、核心模拟目标

用软件模拟一整套工业物联网现场的硬件系统：

> 远程平台 ←→ 4G DTU 传输设备 ←→ Modbus 接口的传感器 / 从站设备

整个过程不需要任何真实硬件，所有通信、数据都在本地软件中模拟完成。

***

## 二、你要模拟的两个核心组件

对外它表现为一个完整的物联网终端设备，内部则拆分为**两个完全解耦的独立模块**，两个模块的代码可以独立开发、修改、调试，互不影响，就像真实场景中两个独立的硬件设备一样：

> 两个模块之间通过本地的标准 Modbus TCP 协议通信：DTU 模拟模块作为 Modbus 主站，访问本地 Modbus 从站模块的 502 端口，通过标准协议完成数据交互。这种设计让你可以单独修改任意一个模块的代码，只要标准接口不变，就不会影响另一个模块的运行。

注：真实硬件场景中，DTU 与 Modbus 从站是通过 RS485 总线进行 Modbus RTU 通信，模拟阶段我们用更易实现的本地 Modbus TCP 来模拟这个传输过程，既简化了实现复杂度，又完整保留了 Modbus 的指令交互逻辑，足够还原真实的设备行为，满足平台测试需求。

### 1. 4G DTU 设备模拟

模拟 4G DTU（数据传输单元）的功能，负责和你的平台进行远程通信：

- **通信能力**：作为 MQTT 客户端，连接你本地的 MQTT Broker（1883 端口）
- **设备标识**：虚拟设备序列号为 `A1B2C3D4`，对应专属的通信主题：
  - 订阅下行主题：`/dtu/A1B2C3D4/down`，接收平台下发的所有指令
  - 发布上行主题：`/dtu/A1B2C3D4/up`，把设备的响应、采集到的数据上报给平台

### 详细功能支持列表

你定义的平台指令功能码，两个模块的支持情况如下：

| 功能码  | 方向 | 功能名称   | 4G DTU 需要支持                          | Modbus 从站需要支持 |
| ---- | -- | ------ | ------------------------------------ | ------------- |
| 0x00 | 上行 | 心跳包    | ✅ 定时30秒发送                            | ❌ 不需要         |
| 0x01 | 下行 | 模组配置查询 | ✅ 接收并转发 Modbus 查询                    | ❌ 不需要         |
| 0x01 | 上行 | 模组配置上发 | ✅ 解析 Modbus 配置并上发                    | ❌ 不需要         |
| 0x02 | 下行 | 下发模组配置 | ✅ 解析并配置 Modbus 参数                    | ❌ 不需要         |
| 0x02 | 上行 | 模组配置结果 | ✅ 上发配置结果                             | ❌ 不需要         |
| 0x03 | 下行 | 数据配置查询 | ✅ 接收并转发 Modbus 查询                    | ❌ 不需要         |
| 0x03 | 上行 | 数据配置上发 | ✅ 解析 Modbus 响应并上发                    | ❌ 不需要         |
| 0x04 | 下行 | 下发数据配置 | ✅ 解析并写入本地配置                          | ❌ 不需要         |
| 0x04 | 上行 | 配置结果   | ✅ 上发配置结果                             | ❌ 不需要         |
| 0x05 | 上行 | 数据上发   | ✅ 根据0x02下发的模组配置来轮询 / 触发读取 Modbus 并上发 | ✅ 提供寄存器数据     |
| 0x06 | 下行 | 远程置数   | ✅ 解析并写入 Modbus 寄存器                   | ✅ 支持写寄存器      |

### 2. Modbus TCP 从站设备模拟

模拟带 Modbus 接口的传感器 / 从站设备，提供真实的传感器数据交互能力：

- **通信能力**：在本地 `127.0.0.1:502` 端口开启 Modbus TCP 服务，模拟标准的 Modbus 从站
- **多可拆装从站支持**：模拟真实 RS485 总线的可插拔设备特性，还原从站可拆装的真实场景，支持挂载丰富的不同类型的从站设备：
  - 支持挂载多个独立的 Modbus 从站，每个从站拥有独立的 slave ID、独立的寄存器数据，互不干扰
  - 支持动态添加 / 移除从站，模拟设备的拆装操作：移除从站后，DTU 访问该 slave ID 会返回通信超时，还原设备断开的场景；添加从站后即可恢复正常通信
  - 每个从站都完整支持标准 Modbus 的四类寄存器区，完全参考真实工业器件的机制，可模拟各种类型的真实从站：

| ---- | ------------------------- | ------ | ---- | ----------------------- | ---------------- | -------- | ------------------------ |
| 0    | 线圈寄存器 (Coils)             | 1 位布尔值 | 可读写  | 00001-09999（可扩展至 65535） | 0x0000-0xFFFF    | 2000 个   | 控制继电器、开关、阀门、电机启停等数字输出    |

| 3    | 输入寄存器 (Input Registers)   | 16 位字  | 只读   | 30001-39999（可扩展至 65535） | 0x0000-0xFFFF    | 125 个    | 采集温度、压力、流量、电流电压等模拟量传感器数据 |

### 3. 变量配置增强（语义化数据上发）

为支持更灵活的数据转换和展示，变量配置新增以下字段：

| 字段名     | 类型     | 说明                                      | 默认值   |
| :------- | :------ | :-------------------------------------- | :----- |
| Scale    | float64 | 缩放因子，用于数值转换。实际值 = 原始值 × Scale + Offset | 1.0   |
| Offset   | float64 | 偏移量，用于数值转换                                  | 0.0    |
| RegCount | int     | 寄存器数量，表示该变量占用的寄存器个数                     | 1      |
| ByteOrder| string  | 字节序，支持：ABCD(大端)、BADC、CDAB、DCBA(小端)       | ABCD   |
| Unit     | string  | 单位，如 "℃"、"%"、"V" 等                         | ""     |

### 4. 数据上发流程（InfluxDB 写入）

平台收到 DTU 上发的数据后，经过以下处理流程：

1. **数据解析**：根据变量配置（ByteOrder）解析原始字节
2. **数值转换**：应用 Scale 和 Offset 计算实际值
3. **语义化写入**：将处理后的数据写入 InfluxDB `device_data` measurement

InfluxDB 写入数据结构 `SemanticDataItem`：

| 字段         | 类型          | 说明                     |
| :--------- | :---------- | :--------------------- |
| DevSerial  | string      | 设备序列号                  |
| VarName    | string      | 变量名称                   |
| SlaveAddr  | int         | Modbus 从站地址             |
| ModbusType | int         | Modbus 区域类型（0/1/3/4）   |
| ModbusAddr | int         | 寄存器地址                  |
| ActualValue| interface{} | 实际值（缩放+偏移后的值）       |
| RawValue   | string      | 原始值（十六进制字符串）         |
| Unit       | string      | 单位                      |

## 三、内部联动逻辑（模拟真实工作流程）

两个模拟组件会自动联动，完全复现真实设备的工作流程：

1. 当 DTU 模拟部分收到平台的 MQTT 指令后：

- 如果是 DTU 自身的配置类指令：按照功能码处理，完成配置后把结果打包成 MQTT 消息上报给平台
- 如果是 Modbus 读写类指令：把平台的指令转换成标准 Modbus 请求，发给本地的 Modbus 从站模拟服务

1. Modbus 从站模拟部分收到请求后，读取 / 更新本地的虚拟寄存器数据，返回标准的 Modbus 响应
2. DTU 模拟部分拿到 Modbus 响应后，把数据打包成 MQTT 上报消息，发送给平台

整个过程对平台完全透明，和真实 DTU 采集 Modbus 传感器数据、远程上报给平台的工作流程完全一致。
