## 二、决策传导机制详细分析

### 2.1 L0 → L1 传导链路（ L0决定L1 ）

#### 2.1.1 从agreement.md到自适应平台功能扩展文档.md

**信息传递方式**：
- 直接引用：agreement.md的数据类型定义被直接引用
- 原则指导：协议规范中的数据类型定义指导扩展字段设计
- 参数约束：Scale/Offset/RegCount/ByteOrder字段约束来自协议规范

**决策转化过程**：

| L0协议条款 | L1扩展决策 | 转化说明 |
| :-------- | :-------- | :------- |
| bool类型定义 | ModbusType 0/1区 | 位变量需要Scale=1, Offset=0 |
| uint16/int16类型 | ModbusType 3/4区，字变量 | 需要RegCount=1, ByteOrder |
| float32类型 | 需要RegCount=2 | 2个寄存器存储4字节 |
| float64类型 | 需要RegCount=4 | 4个寄存器存储8字节 |
| 数值转换公式 | Scale/Offset字段 | 直接转化为配置字段 |

**影响程度**：★★★★★ (完全依赖)

#### 2.1.2 从agreement.md到4G DTU 物联网平台 - 项目部署文档.md

**信息传递方式**：
- 直接引用：协议格式定义被完整引用
- 规范转化：04/05/06功能码格式直接转化为部署文档的协议说明
- 参数传递：字节数、字段顺序完全一致

**决策转化过程**：

| L0协议条款 | L1部署文档决策 | 转化说明 |
| :-------- | :------------ | :------- |
| 04下发格式 | 7.3节04下发协议格式 | 1字节功能码+2字节组数+n×6字节配置 |
| 05上发格式 | 7.3节05上发协议格式 | 1字节功能码+2字节组数+n组数据 |
| 06远程置数格式 | 7.3节06下发协议格式 | 1+1+2+2+数值 |
| Modbus区域定义 | 7.2节Modbus区域定义表 | 0/1/3/4区映射 |

**影响程度**：★★★★★ (完全依赖)

---

### 2.2 L1 → L2 传导链路（ L2适配L1 ）

#### 2.2.1 从L1文档到DTU+Modbus模拟器需求总结_整理版.md

**信息传递方式**：
- 功能扩展：基于L1的变量配置扩展，设计模拟器的数据采集需求
- 流程延伸：L1的InfluxDB写入流程延伸为模拟器的数据上发流程
- 规范细化：L1的字段定义细化为具体的变量配置要求

**决策转化过程**：

| L1扩展字段 | L2模拟器需求 | 转化说明 |
| :-------- | :---------- | :------- |
| Scale/Offset | 数据转换需求 | 模拟器需支持按比例缩放数据 |
| ByteOrder | 字节序处理 | 模拟器需按指定字节序发送数据 |
| RegCount | 多寄存器读取 | 模拟器需支持跨寄存器数据采集 |
| Unit | 单位标注 | 模拟器需在数据中携带单位信息 |
| SemanticDataItem | 数据结构定义 | 需求文档定义了完整的数据项结构 |

**影响程度**：★★★★☆ (强依赖)

#### 2.2.2 从L1文档到DTU+Modbus 模拟器 全新设计与实现方案.md

**信息传递方式**：
- 技术选型指导：基于L1的数据类型定义确定技术实现方案
- 架构约束：L1的语义化写入要求影响架构设计
- 接口定义：L1的字段定义影响接口参数设计

**决策转化过程**：

| L1扩展要求 | L2设计方案 | 转化说明 |
| :-------- | :-------- | :------- |
| 变量配置扩展 | ConfigManager模块 | 管理scale/offset/regCount/byteOrder |
| InfluxDB写入 | DataRegistry模块 | 维护数据注册表 |
| 多数据类型支持 | VirtualDevice模块 | 支持四类寄存器区 |
| 语义化数据 | SemanticDataItem结构 | 定义标准化数据结构 |

**影响程度**：★★★★☆ (强依赖)

**决策转化过程**：

| L2设计方案 | L3实现 | 代码文件 |

### 9.2 Critical级别问题

#### Q-001: 静默异常捕获导致数据丢失

| 属性 | 值 |
| :--- | :--- |
| **文件** | `c:\Users\JERRY\Desktop\gp\src_5-2\simulator_v3\protocol\remote_write_handler.py` |
| **行号** | 68-73 |
| **类型** | 未处理异常 |
| **严重程度** | Critical |
| **分类** | 逻辑缺陷 |

**问题代码**：

```python
except struct.error as e:
    logger.error(f"Failed to parse remote write payload: {e}")
    return None
except Exception as e:
    logger.error(f"Error handling remote write: {e}")
    return None
```

**问题分析**：
所有异常都被静默捕获并返回`None`，调用者无法区分具体错误类型，可能导致重要操作失败被忽略。

**修复方案**：

1. 新增自定义异常类：
   - `RemoteWriteError`：基类异常
   - `PayloadParseError`：payload解析错误
   - `ModbusWriteError`：Modbus写入错误
   - `UnsupportedDataTypeError`：不支持的数据类型错误

2. 新增错误码常量：
   - `ERROR_CODE_SUCCESS = 0`
   - `ERROR_CODE_PARSE_FAILED = 1`
   - `ERROR_CODE_WRITE_FAILED = 2`
   - `ERROR_CODE_UNSUPPORTED_TYPE = 3`

3. 添加详细日志记录，包含时间戳、异常类型、错误信息及上下文数据

4. 返回结构化错误响应而非`None`

**修复状态**：✅ 已修复
