## 🎯 迁移策略：渐进式迁移

### 原则
1. ✅ **新旧兼容**：迁移期间两个方案同时可用
2. ✅ **逐个迁移**：先迁移一个组件，验证通过后再继续
3. ✅ **可回滚**：每个迁移步骤都可以独立回滚

---

## 📋 迁移步骤

### 阶段一：API层扩展（低风险）

**文件**：`src/api/index.js`

**任务**：
1. 新增方案2的4个API方法
2. 保留原 `downpayload` 方法不变

**新增接口**：
```javascript
{
    // 新增方案2接口
    sendModuleConfig(data) { /* ... */ },  // /sendcod/module-config
    sendDataConfig(data) { /* ... */ },    // /sendcod/data-config
    queryDataConfig(data) { /* ... */ },   // /sendcod/query-config
    remoteWrite(data) { /* ... */ }       // /sendcod/remote-write
}
```

---

### 阶段二：迁移查询数据配置（最简单）

**文件**：`components/variables/Features.vue`

**迁移点**：`handleQuery03` 函数

**改动**：
```javascript
// 旧代码
await api.downpayload({ serial: props.deviceSn, code: '03' })

// 新代码
await api.queryDataConfig({ devSerial: props.deviceSn })
```

---

### 阶段三：迁移模组配置（DeviceDownDialog.vue）

**文件**：`components/DeviceDownDialog.vue`

**迁移点**：`handleConfirm` 函数

**改动**：
1. 删除前端十六进制编码逻辑（`code` 拼装）
2. 改用 `api.sendModuleConfig`
3. 传入 JSON 参数（`devSerial`, `sendMode`, `configData`, `baudRate`）

**注意事项**：
- 支持单个设备和批量设备
- configData 需正确转换（十进制整数）
- sendMode 从十六进制字符串转字节（'00' → 0）

---

### 阶段四：迁移数据配置（Features.vue）

**文件**：`components/variables/Features.vue`

**迁移点**：`handleSend` 函数

**改动**：
1. 删除 `build04FunctionCode` 函数（或保留用于预览显示）
2. 构造 JSON 数据格式传给 `api.sendDataConfig`
3. 数据结构：`{ devSerial, entries: [{ slaveAddr, type, startAddr, length }, ...] }`

**优化**：
- 前端可删除分组合并逻辑，完全交给后端优化器！
- 只需要传原始变量列表即可！

---

### 阶段五：迁移远程置数（RemoteWriteDialog.vue）

**文件**：`components/variables/RemoteWriteDialog.vue`

**迁移点**：`submit` 函数

**改动**：
1. 删除前端组包逻辑
2. 改用 `api.remoteWrite`
3. 传入 JSON 参数（`devSerial`, `dataType`, `startAddr`, `quantity`, `values`）

---

### 阶段六：清理和优化（可选）

**可选操作**：
1. 可以删除前端不再使用的十六进制编码函数
2. 可以优化 UI（移除 HEX 预览显示）
3. 添加更好的错误处理和加载状态

## 📝 建议迁移顺序

**优先级**：
1. API层扩展（风险最低）
2. 查询数据配置（最简单）
3. 模组配置（有批量操作，稍复杂）
4. 数据配置（最复杂，优化逻辑集中）
5. 远程置数（最后）
