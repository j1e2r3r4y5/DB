# 变量管理与数据管理页面拆分 — 优化设计方案 v2.0

## 一、背景与现状分析

### 1.1 当前问题

| 指标 | 变量管理 | 数据管理 | 设备管理（参照） |
|------|:-------:|:-------:|:--------------:|
| 核心文件行数 | 630行 | 757行 | 430行 |
| 子组件数 | 7个 | 1个 | 若干个独立页面 |
| 功能密度 | 列表+新建+编辑+导入+下发+置数+回溯+批量删除 | 实时数据+沙箱+搜索+排序+统计+导出+趋势图 | 列表+增删改查 |
| 弹窗数量 | 6个弹窗 | 2个弹窗 | 0个弹窗 |

**核心矛盾**：变量管理和数据管理都是「单页面 + 多弹窗」架构，所有功能集中在同一个 URL 下，导致：
- 单个文件过于冗长（630~757行），维护困难
- 功能间耦合严重，修改一处可能影响其他
- 弹窗深嵌套（下发弹窗里还有表格、优化详情），用户体验差
- 无法通过 URL 直接分享/跳转到特定功能

### 1.2 拆分目标

1. **功能解耦**：每个独立功能拆为独立页面，代码量控制在 200~300 行
2. **路由直达**：每个子功能都有独立 URL，支持直接跳转
3. **用户操作路径清晰**：类似「设备管理」的侧边栏子菜单结构
4. **保持现有功能不变**：拆分后所有原有功能保留

### 1.3 v2.0 优化要点

在 v1.0 方案基础上，v2.0 做了以下深度优化：

1. **下发配置页（原 Features.vue 561行）**：拆分为 4 个独立子页面，而非单一的迁移页，每个页面聚焦一个操作步骤
2. **导入变量页（原 ImportVariablesDialog.vue 466行）**：内部 3 种导入方式拆分为 tab 页，各 tab 有独立 URL
3. **数据管理**：将真实数据与沙箱数据拆为独立子页面，统计功能独立为子页面
4. **增加公共模块**：提取 Modbus 计算工具、导入解析器、Seed 生成器等纯函数模块，便于跨页面复用和单元测试
5. **增加面包屑导航**：每个子页面顶部显示面包屑，清晰指示当前位置和返回路径

### 2.5 关键页面详细设计

#### variables.vue（变量列表页）
- **保留功能**：设备选择器、变量表格（带虚拟滚动）、搜索筛选、全选/跨页全选、批量删除、单行编辑/删除、刷新、撤销变更
- **跳转出口**：
  - "新建变量"按钮 → `router.push('/home/variables/create?devId=' + devId)`
  - "导入变量"按钮 → `router.push('/home/variables/import?devId=' + devId)`
  - "下发配置"按钮 → `router.push('/home/variables/send?devId=' + devId)`
  - "远程置数"按钮 → `router.push('/home/variables/remote-write?devId=' + devId)`
  - 编辑按钮 → `router.push('/home/variables/edit/' + row.id)`
- **设备选择器**：保留在列表页顶部，切换设备时重新加载列表
- **URL 参数**：`?devId=xxx` 支持外部指定设备

#### SendConfig.vue（下发配置主容器页）
- **布局**：
  ```
  ┌──────────────────────────────────┐
  │  面包屑: 变量管理 > 下发配置       │
  │  设备: [设备名称] (SN: xxxxxx)    │
  ├──────────────────────────────────┤
  │  步骤条: ①优化分组 → ②HEX码 → ③确认下发  │
  │  [可选] ④批量查询                  │
  ├──────────────────────────────────┤
  │                                  │
  │      <router-view>               │
  │      子页面内容区域                │
  │                                  │
  ├──────────────────────────────────┤
  │  全局操作栏: [导出结果] [确认下发]  │
  └──────────────────────────────────┘
  ```
- **设备上下文**：通过 URL 参数 `?devId=xxx` + Pinia store 传递
- **数据共享**：各子页面通过 provide/inject 或 store 共享计算结果

#### SendOptimize.vue（下发优化子页）
- **功能**：
  - 调用 `getGroupDetails()` 进行 Modbus 分组
  - 调用 `callBackendOptimization()` 尝试后端优化
  - 后端失败时回退到 `calculateOptimizationResult()` 前端计算
  - 展示优化前后对比表格（分组数、寄存器总数、指令字节数）
  - 展示每个分组的详细地址范围
- **数据流**：计算结果通过 store 共享给 SendHex / SendConfirm

#### SendHex.vue（HEX码展示子页）
- **功能**：
  - 从 store 读取计算结果
  - 调用 `hexBytes()` 将字节数组格式化为 HEX 字符串
  - 按功能码分组展示（高亮语法）
  - "复制 HEX 码"按钮 → `navigator.clipboard.writeText()`
  - "导出 HEX"按钮 → 调用 `exportUtils.exportToTxt()`
- **独立演示**：支持通过 URL 参数 `?hex=...` 直接展示外部传入的 HEX 码

#### ImportVariables.vue（导入变量主容器页）
- **布局**：
  ```
  ┌──────────────────────────────────┐
  │  面包屑: 变量管理 > 导入变量       │
  │  设备选择器 [下拉框]              │
  ├──────────────────────────────────┤
  │  步骤条: ①选择方式 → ②解析预览 → ③执行导入  │
  │  [Tab导航] 文件上传 | 粘贴文本 | Seed生成  │
  ├──────────────────────────────────┤
  │                                  │
  │      <router-view>               │
  │      子页面内容区域                │
  │                                  │
  ├──────────────────────────────────┤
  │  导入进度条 + [执行导入] 按钮      │
  └──────────────────────────────────┘
  ```
- **Tab 与路由联动**：
  - `/home/variables/import/file` → 默认文件上传 tab
  - `/home/variables/import/paste` → 粘贴文本 tab
  - `/home/variables/import/seed` → Seed生成 tab
  - Tab 切换即路由跳转，支持 URL 直达

#### ImportSeed.vue（Seed生成导入子页）
- **功能**：
  - 种子输入框 + "生成预览"按钮
  - 调用 `generateFromSeed()` 生成变量列表
  - 预览表格展示：变量名、数据类型、地址、长度
  - "导出种子数据"按钮 → 调用 `exportUtils.exportToTxt()`
  - "执行导入"按钮 → 调用 `variableService.handleImport()`
- **URL 参数**：支持 `/home/variables/import/seed?seed=abc123` 直达预填充

## 六、实施建议

### 6.1 优先级与分阶段实施

```
第一阶段（高优先级）- 先做最独立、收益最高的功能：
├── 变量管理：
│   ├── variables.vue 瘦身（移除弹窗，改为页面跳转）
│   ├── VariableCreate.vue（新建变量页）
│   └── VariableEdit.vue（编辑变量页）
├── 数据管理：
│   ├── 提取公共模块（dataUtils.js）
│   ├── DataRealtime.vue（实时数据页瘦身）
│   └── DataSandbox.vue（沙箱数据页）
│
├── 公共模块：
│   └── modbus.js（Modbus 计算工具集）
│
├── 新增路由 + 侧边栏菜单

第二阶段（中优先级）- 需较复杂的逻辑迁移：
├── 变量管理：
│   ├── SendConfig.vue + SendOptimize.vue（下发优化，核心逻辑迁移）
│   └── SendHex.vue（HEX码展示）
├── 数据管理：
│   ├── DataTrend.vue（趋势图独立页，带多变量叠加）
│   └── DataExport.vue（数据导出多格式支持）
│
├── 公共模块：
│   └── seedGenerator.js + importParser.js

第三阶段（低优先级）- UI 较重的功能：
├── 变量管理：
│   ├── SendConfirm.vue（下发确认）
│   ├── SendQuery.vue（批量查询）
│   ├── ImportFile.vue / ImportPaste.vue / ImportSeed.vue（导入三子页）
│   └── RemoteWrite.vue（远程置数）
├── 数据管理：
│   ├── DataHistory.vue（历史数据页）
│   └── DataStats.vue（数据统计页）
│
├── 公共模块：
│   └── exportUtils.js + variableService.js
```

### 6.2 迁移策略

1. **新建页面路由**：先定义路由和侧边栏菜单
2. **保留原页面**：拆分过程中原功能保持可用，弹窗组件暂不删除
3. **逐步迁移**：每次迁移一个功能，独立验证
4. **提取公共模块**：在迁移过程中同步提取纯函数到 `src/utils/`
5. **删除弹窗代码**：确认新页面正常工作后，删除原弹窗组件
6. **回归测试**：每个阶段完成后，确保变量列表和实时数据页的核心功能不受影响

### 6.3 注意事项

- **设备选择上下文**：变量管理和数据管理都依赖「当前选择的设备」，跨页面跳转时需通过 URL 参数或 Pinia store 传递设备 ID
- **代码复用**：`Screening.vue`（设备选择器）继续作为通用组件，各页面按需引入
- **自动刷新**：数据管理的自动刷新（每3秒）只在 DataRealtime.vue 保留，其他页面不需要
- **性能**：独立页面加载更轻量，减少不必要的渲染
- **404 处理**：下发配置和导入变量的子路由在无设备选中时，应重定向到设备选择页
