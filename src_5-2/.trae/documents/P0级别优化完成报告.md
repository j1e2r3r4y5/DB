### 2. 优化前基准数据对齐（前后端统一）

#### 问题分析
- 前端显示"合并后05上报数据包长度"作为优化前基线
- 但后端返回的是原始未合并的长度
- 导致前后端数据不一致，用户困惑

#### 修复方案
**后端修改** (`dev_back_end/dev/internal/logic/sendcod.go`):
- 将 DefaultOptimizer 合并后的结果作为优化前基准
- 使用 `defaultResult.OptimizedPayload` 替代 `defaultResult.OriginalPayload`
- 使用 `defaultResult.OptimizedSegments` 替代 `len(items)`

**前端修改** (`4G_dev_front/4G_dev/src/components/variables/Features.vue`):
- 移除 `rawUploadLength` 相关计算
- 直接使用 `uploadLength` 作为优化前基线
- 显示文字改为"合并后05上报数据包长度（优化前基线）"

#### 验证结果
通过实际测试，对于有间隙的变量：
- 优化前（DefaultOptimizer合并后）: 31字节
- 优化后（PayloadOptimizer）: 27字节
- 节省: 4字节 (12.9%)
- 前后端显示一致

### 3. Python 模拟器修复

#### 3.1 address_segment.py 字段解析修复

**问题**:
- `unit` 字段（如"°C"、"%RH"）被错误地解析为 `init_value`
- 导致 WARNING: "无法解析初始值"

**修复** (`simulator_v1536/data/address_segment.py`):
- 第7列: unit（单位）
- 第8列: init_value（初始值）
- 正确分离两个字段的解析逻辑

**代码修改**:
```python
# 修复前：unit 和 init_value 混淆
if len(item) > 6 and str(item[6]).strip() not in ['', '-', 'None']:
    # 处理初始值

# 修复后：正确分离
if len(item) > 6 and str(item[6]).strip() not in ['', '-', 'None']:
    segment.unit = str(item[6])  # 第7列是 unit
if len(item) > 7 and str(item[7]).strip() not in ['', '-', 'None']:
    val_str = str(item[7])  # 第8列是 init_value
    # 解析初始值
```

## 五、监控告警体系详情

### 架构
```
后端 monitor 模块 → /health /stats /metrics 端点
                            ↓
              Vue 主页（实时展示，15秒刷新）
```

### 监控 API
| 端点 | 返回内容 |
|------|---------|
| GET /health | MySQL/Redis/InfluxDB/MQTT 健康状态 |
| GET /stats | 设备在线数、MQTT 收发数、数据点数、运行时间 |
| GET /metrics | Prometheus 格式指标 |

### 自动检测
- 设备离线检测：60 秒周期，3 分钟阈值
- 设备在线指标：30 秒周期更新
- MQTT 消息计数：自动集成到 messageHandler
- 钉钉告警：设备离线/恢复自动通知
