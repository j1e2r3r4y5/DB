# 4G DTU 通信协议更新规范

## 一、变更原因

原始协议文件 `doc_.md` 存在以下问题：
1. **0x05 数据上发格式不完整** - 缺少从站地址(SlaveAddr)和数据类型(ModbusType)字段，导致无法正确解析设备上发的具体数据项
2. **Modbus区域类型描述不明确** - 仅标注"0-4区"，未说明具体区域含义
3. **缺少Modbus区域定义参考文档** - 新协议新增了Modbus区域定义表格

新协议文件 `agreement.md` 解决了以上问题，使协议更加完整和明确。

## 二、协议对比分析

### 2.1 功能码 0x00 心跳包（无变化）

| 方向 | 格式 | 说明 |
|------|------|------|
| 上发 | `0x00` | 无内容心跳包 |

### 2.2 功能码 0x01 上发模组配置（描述澄清）

| 方向 | 旧协议 | 新协议 |
|------|--------|--------|
| 上发 | `1字节功能码 1字节发送模式 2字节配置数据 1字节波特率` | `1字节功能码 1字节发送模式 2字节配置数据 1字节波特率` |

**变更说明**: 描述文字从"线圈器变化触发发送"更正为"线圈变化触发发送"，数据格式无变化。

### 2.3 功能码 0x02 上发模组配置结果（无变化）

| 方向 | 格式 |
|------|------|
| 上发 | `1字节功能码 1字节成功状态` |

成功状态定义：
- `0x00`: 成功
- `0x01`: 打开存储错误
- `0x02`: 写入存储失败
- `0x03`: 触发模式错误
- `0x04`: 数据接收长度错误
- `0x05`: 波特率配置错误

### 2.4 功能码 0x03 数据配置上发（描述澄清）

| 方向 | 旧协议 (第58行) | 新协议 (第53行) |
|------|-----------------|-----------------|
| 上发 | `1字节从站地址 1字节类型（0-4区） 2字节数据地址 2字节数据长度` | `1字节从站地址 1字节类型（0134区，划分参考下文Modbus 区域定义） 2字节数据地址 2字节数据长度` |

**变更说明**: 类型字段描述更明确，强调支持0、1、3、4区域（不含2区），并新增Modbus区域定义参考。

### 2.5 功能码 0x04 数据配置下发（描述澄清）

| 方向 | 旧协议 (第65行) | 新协议 (第60行) |
|------|-----------------|-----------------|
| 下发 | `1字节从站地址 1字节类型（0-4区） 2字节数据地址 2字节数据长度` | `1字节从站地址 1字节类型（0134区，划分参考下文Modbus 区域定义） 2字节数据地址 2字节数据长度` |

**变更说明**: 同0x03，类型描述更明确。

### 2.6 功能码 0x05 数据上发 **（重大变更）**

| 方向 | 旧协议 (第73-77行) | 新协议 (第68-72行) |
|------|--------------------|--------------------|
| 上发 | `1字节功能码 2字节数据数量`<br>`按顺序每个数据具有：`<br>`2字节数据长度（单位字节） 数据长度个字节数据` | `1字节功能码 2字节数据数量`<br>`按顺序每个数据具有：`<br>`1字节从站地址 1字节数据类型 2字节地址 2字节数据长度（单位字节） 数据长度个字节数据` |

**重大变更说明**:
- **旧协议**: 每个数据项只包含 `2字节数据长度 + 数据内容`，缺少数据源和类型标识
- **新协议**: 每个数据项包含完整的Modbus元数据 `从站地址 + 数据类型 + 地址 + 长度 + 数据内容`

新协议数据项格式:
```
1字节从站地址 | 1字节数据类型 | 2字节地址 | 2字节数据长度 | N字节数据
```

### 2.7 功能码 0x06 远程置数（无变化）

| 方向 | 格式 |
|------|------|
| 下发 | `1字节功能码 1字节类型（0区 4区） 2字节开始地址 2字节数量 数值` |
| 上发 | `1字节功能码 1字节类型 2字节开始地址 2字节数量 1字节成功状态` |

### 2.8 新增 Modbus 区域定义表

| 区域编号 | 官方名称 | 数据类型 | 读写权限 | 协议地址 (0-based) | 最大读取数量 |
|----------|----------|----------|----------|-------------------|--------------|
| 0 区 | 线圈寄存器 (Coils) | 1位布尔值 | 可读写 | 0x0000-0xFFFF | 2000个 |
| 1 区 | 离散输入寄存器 | 1位布尔值 | 只读 | 0x0000-0xFFFF | 2000个 |
| 3 区 | 输入寄存器 | 16位字 | 只读 | 0x0000-0xFFFF | 125个 |
| 4 区 | 保持寄存器 | 16位字 | 可读写 | 0x0000-0xFFFF | 125个 |

### 3.2 0x05功能码解析逻辑变更

**当前实现问题**:
```go
// 旧协议解析 - 缺少从站地址和类型
for readBytes+6 <= dataItemBytes {
    // 这里只有 2字节长度 + 数据，缺少从站地址和类型
    dataLen, _ := scanner.Next(2)  // 长度
    dataValue, _ := scanner.Next(valueLen)  // 数据
}
```

**新协议解析需要**:
```go
// 新协议解析 - 完整Modbus元数据
for readBytes+7 <= dataItemBytes {
    slaveAddr, _ := scanner.Next(1)   // 从站地址 (新增)
    modbusType, _ := scanner.Next(1)  // 数据类型 (新增)
    dataAddr, _ := scanner.Next(2)    // 地址
    dataLen, _ := scanner.Next(2)     // 长度
    dataValue, _ := scanner.Next(valueLen)  // 数据
}
```

### 4.1 internal/logic/payload.go

#### 4.1.1 功能码0x05解析逻辑修改

**位置**: `case "05"` 分支 (第253-329行)

**修改前**:
```go
case "05": // 上发数据
    Featurescode = 0x05
    lenBytes, err := scanner.Next(2)
    if err != nil {
        g.Log().Error(ctx, "解析数据区总长度失败", err)
        return false, 0, nil, nil, err
    }
    totalLen := int(lenBytes[0])<<8 | int(lenBytes[1])
    g.Log().Debug(ctx, "数据区总长度", totalLen)
    // 已经读取了3字节（功能码+长度），还剩totalLen-3字节为数据项
    dataItemBytes := totalLen - 3
    readBytes := 0
    for readBytes+6 <= dataItemBytes {
        slaveAddr, _ := scanner.Next(1)
        ModbusType, _ := scanner.Next(1)
        dataAddr, _ := scanner.Next(2)
        dataLen, _ := scanner.Next(2)
        // ... 旧逻辑
    }
```

**修改后**:
```go
case "05": // 上发数据
    Featurescode = 0x05
    lenBytes, err := scanner.Next(2)
    if err != nil {
        g.Log().Error(ctx, "解析数据区总长度失败", err)
        return false, 0, nil, nil, err
    }
    totalLen := int(lenBytes[0])<<8 | int(lenBytes[1])
    g.Log().Debug(ctx, "数据区总长度", totalLen)
    // 已经读取了3字节（功能码+长度），还剩totalLen-3字节为数据项
    dataItemBytes := totalLen - 3
    readBytes := 0
    // 新协议: 每个数据项 = 1字节从站地址 + 1字节类型 + 2字节地址 + 2字节长度 + N字节数据
    for readBytes+6 <= dataItemBytes {
        slaveAddr, _ := scanner.Next(1)    // 1字节从站地址 (新增)
        modbusType, _ := scanner.Next(1)   // 1字节数据类型 (新增)
        dataAddr, _ := scanner.Next(2)     // 2字节地址
        dataLen, _ := scanner.Next(2)      // 2字节数据长度
        length := int(dataLen[0])<<8 | int(dataLen[1])

        // 根据Modbus类型计算数据值长度
        var valueLen int
        switch modbusType[0] {

            valueLen = length * 2         // 字

        readBytes += 6 + valueLen
```

## 五、兼容性考虑

### 5.1 向前兼容

由于0x05数据上发是设备主动上报给服务器，服务器端解析逻辑的修改不会影响旧设备。只要设备固件已更新，新协议即可生效。

### 5.2 建议

1. **协议版本协商**: 建议在后续版本中增加协议版本字段，支持服务器与设备之间的协议版本协商
2. **双协议支持**: 短期内的兼容方案可以是根据首个数据包的格式自动识别使用哪个版本的协议解析
3. **配置项**: 可在配置文件中添加 `protocol.version` 配置项，支持切换新旧协议解析逻辑
