### 数据类型定义

**注意**：本项目使用的数据类型与 Modbus 寄存器存储方式对应，不是传统工业协议的 1/2/3/4 分类。

| 类型名称    | 说明               | 存储方式                   | 寄存器占用 |
| :------ | :--------------- | :--------------------- | :---- |
| bool    | 布尔值              | 0或1，按位存储               | 1位    |
| int16   | 有符号16位整数         | -32768-32767           | 1寄存器  |
| int32   | 有符号32位整数         | -2147483648-2147483647 | 2寄存器  |
| float32 | 单精度浮点数(IEEE 754) | 标准浮点格式                 | 2寄存器  |
| float64 | 双精度浮点数(IEEE 754) | 标准浮点格式                 | 4寄存器  |
| string  | 字符串              | 按字节存储                  | 变长    |

**字节序说明**：

- ABCD：大端序（高位在前）
- DCBA：小端序（低位在前）
- BADC：混合序
- CDAB：混合序

## Modbus 区域定义

| 区域编号 | 官方名称                      | 数据类型               | 读写权限    | 逻辑地址 (1-based)             | 协议地址 (0-based) | 最大读取数量 |
| :--- | :------------------------ | :----------------- | :------ | :------------------------- | :------------- | :----- |
| 0 区  | 线圈寄存器 (Coils)             | 1 位布尔值 (ON/OFF)    | **可读写** | 00001-09999 (实际可扩展至 65535) | 0x0000-0xFFFF  | 2000 个 |
| 1 区  | 离散输入寄存器 (Discrete Inputs) | 1 位布尔值 (ON/OFF)    | 只读      | 10001-19999 (实际可扩展至 65535) | 0x0000-0xFFFF  | 2000 个 |
| 3 区  | 输入寄存器 (Input Registers)   | 16 位字 (可存储整数、定点数等) | 只读      | 30001-39999 (实际可扩展至 65535) | 0x0000-0xFFFF  | 125 个  |
| 4区   | 保持寄存器 (Holding Registers) | 16 位字 (可存储整数、定点数等) | **可读写** | 40001-49999 (实际可扩展至 65535) | 0x0000-0xFFFF  | 125 个  |

> **注意：** 16位寄存器可存储整数(0-65535)或定点数(存储值÷10^decimalDigits)。浮点数(IEEE 754)需占2个寄存器(4字节)。

### 怎么读（三步）

1. **先看「配置速查表」**：明文还是 TLS、QoS、心跳间隔都在表里。
2. **再算「一条报文」**：业务 payload 多长（协议里的 0x00/0x04/0x05 等），加上 MQTT 头、主题名、QoS 带来的小报文，最后每条再加一截 **TCP+IP 粗算**（见下表）。
3. **最后按次数乘**：例如每 30 秒一次心跳、一次 0x05，就按秒数折算条数。

配置出处：`config.yaml`（MQTT）、`simulator_v3/config.py` 与 `core/mqtt_client.py`、`internal/logic/mqtt.go`。

### 手算时用的「加一层」经验数（理想、无重传）

这些是**工程估算**，用来把「payload 字节」变成「接近链路的字节」；要精确可对单包抓 Wireshark。

| 加什么            | 建议怎么取                                                                                            | 说明                               |
| :------------- | :----------------------------------------------------------------------------------------------- | :------------------------------- |
| **MQTT 帧本身**   | 按 **MQTT 3.1.1** 数：固定头 + 剩余长度 + **2 字节主题长** + **主题 UTF-8** +（QoS≥1 时 **2 字节报文 ID**）+ **payload** | 主题按字符串实际字节数算                     |
| **QoS 1 额外**   | 每条下行 PUBLISH 再多估 **约 4～8 字节（MQTT 层）**                                                            | 主要是 **PUBACK** 方向的小帧             |
| **QoS 2 额外**   | 每条上行 PUBLISH 再多估 **约 16～32 字节（MQTT 层合计）**                                                        | **PUBREC / PUBREL / PUBCOMP** 一轮 |
| **TCP + IPv4** | 每条独立 TCP 段多估 **约 40～60 字节**                                                                      | 若多个 MQTT 合并在一个 TCP 段里，会摊薄        |
| **TLS**        | 当前为 **0**                                                                                        | 一旦启用，握手 + 加密封装要单独加               |

**合计思路（设备 SIM 侧）**：\
对「每一条」下行或上行 MQTT 报文，用 **「MQTT 整帧（含 QoS 小报文）」+「一段 TCP/IP」** 估一遍，再按一天发了多少条去乘。

### 周期业务（当前模拟器默认值）

来自 `simulator_v3/config.py`；真机间隔不同就改数字。

| 做什么         | 间隔                   | 业务 payload 大概多长            |
| :---------- | :------------------- | :------------------------- |
| 心跳 **0x00** | 每 **30** 秒           | **1** 字节（只有功能码）            |
| 数据 **0x05** | 每 **30** 秒           | 看变量合并结果；示例见上文 **【05上发示例】** |
| Keepalive   | 每 **60** 秒（无其它流量时明显） | MQTT **PING**，很小，但要算次数     |

**稳态心算**：\
例如看 **T 秒**内——

- 心跳条数 ≈ `T ÷ 30`（向下取整），每条 payload 1 字节；
- 0x05 条数 ≈ `T ÷ 30`，每条 payload 按你实际组帧长度；\
  再对 **每一条上行** 按上表加 **QoS2 附加 + TCP 粗算**。

### 一次「数据配置」会话（0x04 / 0x05）

前提：**同一份配置只下发一次**（与当前前端能力一致）。

| 方向 | 内容                   | QoS（与上表一致） |
| :- | :------------------- | :--------- |
| 下行 | 平台发 **0x04** 数据配置    | **1**      |
| 上行 | 设备回 **0x04** 结果      | **2**      |
| 上行 | 设备按配置周期发若干次 **0x05** | 每条 **2**   |

**不要混进 SIM 的**：浏览器访问平台、HTTP、MySQL、InfluxDB、Redis——那是机房流量，不是 DTU 卡流量。

### 和真实账单差在哪（一眼看完）

- 现实有 **重连、重传、DNS、TLS**，真实流量 **≥** 本模型。
- **明文 1883** 与 **生产 TLS** 不能共用同一套数。
- **报价/对账**仍以 **模组统计或运营商账单** 为准；本模型用于 **立项和对比方案**。
